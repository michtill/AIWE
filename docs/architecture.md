# Architecture

The studio controls a private working Git repository containing one shallow starting snapshot and the active editing steps. The starting point is empty on installation, the last publication, or a loaded version when all previous draft work was explicitly removed. Such a load removes previous publication entries from the draft conversation, while published versions remain in production history. Production Git contains only published snapshots, with one parent per publication and annotated version tags. Publication history and previews of published versions read this production repository directly. Chat, progress, credentials and uploads remain in private studio storage. A dedicated preview service isolates user website scripts from the authenticated studio. The publisher has read-only access to studio data and write access only to a fixed production target.

Web Lead combines routing, implementation and basic design. Small edits do not run a fixed team pipeline. Large creative or complex work can use the UI/Code specialist; image capabilities are tools. Deterministic file/browser checks run before accepting work. A read-only verifier judges required criteria for significant changes. One repair precedes bounded escalation; failed changes leave HEAD intact.

Image configuration has two capabilities: precise editing and fast creation. Transparent assets explicitly request the image API's `background=transparent` option and use PNG or WebP. Browser checks supply dimensions and real alpha-pixel counts from a separate context with website JavaScript disabled; these are evidence, not model guesses. Technical failures and verifier failures are reported separately. An invalid conversational answer during implementation or escalation receives bounded protocol correction while preserving the candidate, instead of becoming a successful no-op or terminating immediately.

Role/model mappings are in `src/team.ts` and configurable in Settings. Agent contracts are in `src/instructions.ts`, `src/orchestrator.ts` and `src/workflow.ts`. Models communicate with concise English JSON. Human-facing fields follow the original user's request language; English specialist task descriptions must not change it. User content is not treated as system instructions.

Conversation memory is bounded to six active recent turns and targeted older lookup. The manifest supplies a compact file map; models load only relevant files. Website content, API keys and raw provider transcripts are not sent between all roles by default.

Publication selects a fixed approved commit and performs technical checks again. It is separate from creating or loading drafts. Major versions increment the number. Subversions append a record with `minor`, preserving the original version and immutable tags. The UI groups publications by major number and collapses older subversions.

The English UI catalog is in `public/translations.js` and Czech translations are in `public/translations.cs.js`. Both use stable English snake_case technical keys. `public/locales.js` provides the shared language registry, English fallback and named message parameters. `public/i18n.js` translates keyed UI text and explicitly marked HTML, never arbitrary website content. A compatibility adapter keeps older system messages readable. Language selection is browser-local, with an installation default. Historic model replies keep their original language. The model prompt language is independent of the UI setting.

The system edits static files, not server infrastructure or arbitrary dependency builds. Deterministic browser tests run in an isolated local context with external services blocked. Hosting-level TLS, network policy and production credentials remain administrator responsibilities.

Escalation first adjudicates the failed step using the original brief, candidate diff and actual check evidence. It may repeat verification without changing files (`action: verify`), repair implementation or browser scenarios, or use supported image/import tools. After escalation, the configured escalation model supplies the authoritative read-only verdict instead of returning the candidate to the ordinary verifier. Deterministic checks still run and cannot be overridden; user requirements remain unchanged. Verification records include the actual model, provider and role.

Publishing runs host-managed image cleanup after validating the selected snapshot and rechecks any cleaned snapshot in the browser. It removes unreferenced PNG/JPEG/WebP/SVG assets and consolidates byte-identical images with rewritten local references. Unknown dynamic references are retained. Uploaded originals remain in private upload storage; image bytes from closed unpublished experiments are removed with working history. Images used by published versions remain in production Git. When publishing an intermediate step, newer snapshot trees are preserved exactly and their step references are remapped onto the cleaned publication baseline. No force push to production is used. Web Lead can request the same reversible cleanup with `action: cleanup`; it does not directly delete binary assets.

Every publication exports the selected site tree into a fresh Git repository and creates a production commit with only the previous production commit as its parent. Deployment files outside `site/` come from production. Working commits and unused historical image blobs are never imported. Annotated `sitetiller/published/` tags record version numbers, subversions, descriptions and dates. After successful publication, the working repository is replaced with a shallow baseline of that publication plus any newer active editing steps; their references are remapped without changing their site trees. Closed working commits and their objects are removed. Exact-source retries reuse the deployed commit and metadata. The publisher must be connected to the studio private network and persistently configured through the hosting application environment.

Reality comparison and confirmed loading use the same cached snapshot. When the publisher supports authenticated `GET /snapshot`, the production Git supplies the managed file catalog and the reader fetches each actual HTTP file without rewriting paths. This includes unlinked managed pages and assets. HTTP bytes, not Git bytes, determine the comparison and subsequent load; divergence is disclosed. A read does not push Git or deploy. Limits are 200 files, 20 MB total and 90 seconds; files added outside the catalog and backend/private resources are not included. `SITETILLER_SITE_URL` identifies the public website when the fetch address is internal. Without a compatible connector, the public importer remains available and now merges equivalent root/index aliases without collisions.

Loading a live website identical to the compared snapshot is blocked. Saving the live state as a numbered version is available only when it differs from the latest saved publication. An archive failure restores the draft and its conversation instead of leaving an unreported partial load; a confirmed archive receipt is recovered if its response was lost. The preview reports its document title to the studio header, including navigation to other pages, without exposing studio privileges to website scripts.

Small bounded changes to existing CSS dimensions, colors and spacing use static file/reference checks without browser startup or a verifier call. The host classifies the actual diff; functional, structural, asset, multi-stage or previously failed work retains full checks. Publication always runs its independent complete technical checks, including browser loading.
